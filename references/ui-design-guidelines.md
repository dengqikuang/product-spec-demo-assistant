# 按终端设计原型

每页按这个顺序设计：**确定终端与系统 → 分析用户任务 → 选择终端组件及交互 → 选布局 → 用系统 tokens 并选择图标 → 验证。** PC 后台、APP、移动 H5 和小程序不是同一页面的四种缩放尺寸。共享业务含义和数据可以；组件呈现、导航环境、操作方式和内容密度须适合目标终端。

## 终端和系统

每页在 `DEMO_CONFIG.pages[]` 说明 `surface`、适用时的移动 `terminal`，并设置 `ui.profile` 与 `ui.layout`。`surface` 描述产品系统壳，`terminal` 描述实际设备环境，`profile` 控制现有系统样式，`layout` 说明本页主要工作。受参考图约束时，先保留该系统的导航位置、信息层级及组件风格；只在本次业务范围内修正基础可读性或交互问题。

受支持 profile、layout 和复合组件 recipe 的终端适用范围以 `assets/business-ui/manifest.json` 为准。PC 页面用 `pc-web`；移动页必须精确声明 `app`、`h5` 或 `mini-program`。系统 shell 决定状态栏、胶囊和导航外壳；业务组件由本页实现。不能以一个 `mobile` 配置同时代表三种移动环境。

## 按任务选组件

以下是默认选择指引。已有系统组件和本次参考优先；选型需结合数据比较、选项规模、生效时机、信息量和返回方式。指引不授权增加 Spec 未确认的筛选、分页或页面流程。

| 用户任务 | PC 后台 | APP / H5 / 小程序 |
|---|---|---|
| 浏览、比较记录 | 需要跨行比较时用对齐的表格；行操作清楚，较长操作可分组 | 默认摘要列表或卡片并进入详情；确有比较任务时可用可横向滚动的比较表格 |
| 搜索与筛选 | 搜索和筛选位于列表上方，查询、重置位置稳定；复杂筛选依现有系统 | 搜索栏加简要筛选入口；复杂条件放筛选面板或页面，并清楚提供应用与重置 |
| 填写表单 | 默认单列或对齐的标签/输入列；按业务关系分组，强关联短字段才并排 | 默认单列；标签可辨认且与字段关联；输入法和键盘类型符合字段 |
| 选择选项 | 少量互斥选项用 Radio；多选用 Checkbox；较长枚举用 Select；大量对象检索用可搜索选择器 | 少量选项直接列出；长枚举和对象选择用终端适合的选择面板或选择页，确认和回写明确 |
| 布尔状态 | 立即生效用 Switch；随表单保存提交用 Checkbox | 明示状态与操作结果；控件与标签组成容易触控的入口 |
| 日期与区间 | 使用日期输入、日历或范围控件，标清起止字段 | 使用终端日期控件或移动日期面板；清楚呈现开始、结束及已选值 |
| 确认、编辑 | 简单确认用对话框；保留列表上下文的小任务可用抽屉；长任务用页面 | 短确认用确认框；短选择可用底部面板；长编辑优先独立页面 |
| 浏览更多数据 | 依 Spec 使用表格滚动、分页或每页条数 | 依 Spec 使用分页、加载更多或连续列表；不自行改变数据加载规则 |
| 导航和主要操作 | 复用侧栏、面包屑和工作页签，键盘和鼠标均可达 | 保留 APP、H5 或小程序的返回与导航上下文；主要操作可直接触控，不能依赖 hover |

Radio、Checkbox、Switch、Select 的语义和生效时机参考 [Ant Design 数据录入指引](https://ant.design/docs/spec/data-entry/)。阈值或特定间距如适用，仅是本技能的默认设计选择，不宣称为通用标准。

## 间距与对齐

先沿用 profile 已有尺寸；以下新建无参考业务区时的 tokens 是起点，Agent 可按页面任务和参考做有限调整，并在 `visual` 标注真正影响保留区域的差异。

| Token | PC 后台 | 移动端 |
|---|---:|---:|
| 页面内容边距 | 20px | 16px，另计系统安全区 |
| 区块间距 | 24px | 16px |
| 字段组间距 | 16px | 12px |
| 同组控件间距 | 8px | 8px |
| 正文字号 | 14px | 16px |
| 常用控件高度 | 32px；沿用中台参考时可为 33px | 主要触控目标默认至少 44 CSS px |

内容框架已有 padding 时不重复叠加。PC 页标题、筛选区、表格和主操作沿同一内容网格；表头与数据单元格内边距一致；数值对齐利于比较。同一表单的标签列与输入列起点一致。移动页面按单列组织，标签、辅助说明和错误紧邻字段；固定底部操作须给滚动内容留出空间。小程序胶囊、状态栏等系统组件按其真实尺寸和安全区单独处理。

每个需要机器检查的共同边缘，用 `data-ui-align-group="<name>"` 标记同一组节点。运行时比较其左边缘，超过 1 CSS px 报错；不要将不同容器或有意缩进的元素放进同组。

## 适应性选择图标

图标选型是代表页设计的一部分。Agent 自主完成常规图标选择，随后沿用到同系统其他页面；无需逐个确认。先检查本次参考中已有的图标语言、线性/填充风格和图文组合，再检查当前页导航、工具栏、搜索/筛选、行操作、状态反馈和适用空态是否需要图标辅助识别。未出现这些场景时不添加；不以图标数量判定页面是否合格。

| 场景 | 选择方式 | 母版可用示例 |
|---|---|---|
| 返回、展开与更多操作 | 常用方向符号沿用系统习惯；更多按钮必须真实打开已实现的操作菜单 | `arrow-left`、`chevron-down`、`chevron-right`、`more` |
| 查询、筛选及高频工具栏操作 | 图标加文字便于扫描；搜索输入内可加搜索图标；不和浏览器/控件自带图标重复 | `search`、`filter`、`plus`、`edit`、`delete`、`upload`、`download` |
| 列表/详情中的业务对象 | 同类对象或无缩略图的摘要可用语义准确的对象图标；数据列、金额和每个字段不逐项装饰 | `user`、`store`、`receipt`、`truck`、`gift` |
| 成功、警告、失败和提示 | 图标配状态文字，必要时加语义颜色；不能只靠图形或颜色区分状态 | `check-circle`、`alert-circle`、`x-circle`、`info` |
| 空态 | 仅在已实现的空态中用一个相关图标配原因和已有恢复操作；不是新增业务功能的理由 | 按语义选 `search`、`clipboard`、`gift` 等 |
| 保存、取消、重置和长文案操作 | 文字本身清楚时保留文字；没有准确图标时不以近似图标强行替代 | 不把 `check-circle` 当保存，不把 `arrow-left` 当重置 |

PC 后台重视扫描和密度：导航与工具栏可配图标，密集表格的行操作通常保留文字，避免每个单元格都加图标。移动端重视触控和空间：返回/关闭等熟悉动作可用纯图标，主要提交、危险和不熟悉操作优先保留文字；业务图标不替代 APP、H5、小程序的系统导航组件。无参考的新业务区可从 PC 16px、图文间距 6px，移动 20px、间距 8px 开始；图标实际尺寸与点击区域分别处理，按钮仍满足终端的目标尺寸。同组统一尺寸、线宽、颜色与光学对齐，不混用线性和填充图标，已有系统样式优先。

来源依次为：本次提供/本地已有的系统正式图标（内嵌进单 HTML）→ 母版已注册图标 → 缺少准确图形时补绘简单的同风格 SVG。复杂或品牌图形使用正式资源；拿不到时保留清楚文字，不临摹品牌标志或选用误导图标。母版图标通过 `productDemo.getIconNames()` 或源码确认名称；例如 `alert-circle` 当前实际是三角警告图形，按实际形状与语义选用，不只看名称。不为一次页面需求改共享母版或引入联网图标依赖。具体渲染方式见 `references/demo-guidelines.md` 的图标落地规则。

自检默认页和关键操作态：该出现的图标是否实际渲染、语义是否准确、是否沿用系统风格、文字是否被压缩、图文/同行按钮是否对齐、纯图标按钮是否有名称与足够点击区，状态是否同时有文字。先修复遗漏与混搭，再扩展其余页面；自动 audit 能查未知图标和按钮名称，不能判断视觉必要性，必须查看 Ego Lite 截图。不要因“图标不足”机械给纯文本页面判错。

## 交互和表单基线

- 按钮和输入有可访问名称；表单字段有可见标签或清楚关联的说明。必填、禁用、只读和校验错误均让用户看得懂。
- 键盘可以完成主要任务；焦点清楚可见，顺序符合页面任务。错误靠近相应字段，并给出恢复方法。
- 业务浮层留在当前页面 panel 内。`productDemo.openDialog(pageId, { overlay, dialog, initialFocus, onCancel })` 只用于真正的对话框；对话框须有名称。此 Demo 保留左右讲解栏操作，所以 dialog 使用 `aria-modal="false"`，背景业务控件与三栏讲解区仍可访问，Tab 顺序不被锁在浮层中；Escape 取消，关闭时恢复原焦点。取消回调负责恢复业务草稿和调用 `setPageState`；确认逻辑先保存业务状态再调用返回句柄的 `close()`。抽屉是保留列表上下文的非模态侧栏，应以有名称的 `aside`/region 实现并保留背景列表操作；不要把抽屉直接包装成 dialog 或调用该 helper。若业务需要阻断背景操作，应实现真正的模态对话框，包括 `aria-modal="true"`、背景 inert、Tab 焦点约束与完整恢复，不能复用这个非模态 helper。
- 移动主要操作至少 44 CSS px；桌面主要操作默认至少 32px。自定义控件和系统组件例外必须保持可操作性，并由视觉复核验证。
- 点击目标、键盘、焦点、错误、标签和对话框检查选自 [WCAG 2.2](https://www.w3.org/TR/WCAG22/) 与 [WAI-ARIA dialog guidance](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)。通过所列检查只代表完成这些检查，不代表完整标准认证。

`productDemo.auditUI()` 检查页面 profile、recipe、布局、对齐组、字段名称、点击目标、安全区滚动和底部操作避让，返回 `{ ok, errors, warnings }`。几何和命名可以辅助自动检查；组件是否最适合用户任务、信息密度、层级、颜色和参考忠实度仍要通过 Ego Lite 的真实操作与截图核对。
