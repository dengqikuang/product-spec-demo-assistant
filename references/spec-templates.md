# Spec 文档模板

Spec 是业务范围、规则和结果的唯一基准。只写已确认的产品语言，不写假设、接口、数据库、框架或代码结构。

## 使用方式

- 常规任务使用下面的标准 0～9 结构，简明填完适用内容；不强制补复杂协作、反指标或其他不适用细节。
- 复杂任务只在涉及多个独立表面、高风险动作、复杂权限或指标口径时，在对应 2、5、6、7、8、9 节补充必要细节。
- 快改不重写 0～9，使用文末的“增量说明”结构，并明确未改变的业务基线。
- 第 4 节必须区分现状/存量能力、本次新增、保持不变、明确不做；文末保留 Demo 演示边界。
- 为每项 P0 分配稳定 ID；决定本次结果的规则不得只写“沿用现有”，必须说明现有行为和确认来源。

- 正常场景与结果：...

- 失败/失效场景（复杂或适用时）：...

## 范围矩阵
| 现状/存量能力 | 本次新增 | 保持不变 | 明确不做 |
|---|---|---|---|
| ... | ... | ... | ... |

## 参考与 Demo 边界
- 截图/原型和页面基线：...
- Demo 要演示的入口、流程和结果：...
- Demo 不验证：真实服务、数据落库、生产性能等。

- ...（无则写“无”）

## 7. 信息架构

按产品表面分别说明导航、页面层级、主要区域、字段、操作和状态；不同表面默认独立描述。

### 逐页字段与操作规则

按真实页面设置稳定小标题（如“7.1 任务列表”），供 Demo 右栏引用。只写本次实际存在的控件；已有明确规则可引用准确章节，不重复维护两份。

- 列表：数据范围、默认排序与适用的并列规则、分页/刷新行为。
- 每个字段：含义、来源/计算或取值规则、枚举文案、格式/单位、空值、展示条件。
- 每个筛选：默认值、枚举或动态来源范围、单/多选、组合关系、生效与重置；搜索匹配和时间边界按适用性说明。
- 表单：新建默认/编辑回填、必填、限制、联动、只读条件与校验反馈。
- 操作：出现/禁用条件、输入、状态/数据变化、成功结果、适用失败和恢复。

## 快改增量说明

```markdown
# {需求名称} · 增量说明

## 业务基线
- 已确认 Spec/Demo：...
- 保持不变：价值、角色、产品表面、入口/页面关系、权限、关键状态、数据口径、验收结果。

## 本次改动
- 受影响页面/入口：...
- 新增或调整：...
- 明确不改：...

## Spec/Demo 更新
- Spec 段落：...
- Demo 入口、字段、布局或交互：...

## 受影响检查
- 范围、文案、壳/同步、P0 结果或视觉中的相关项：...
```
